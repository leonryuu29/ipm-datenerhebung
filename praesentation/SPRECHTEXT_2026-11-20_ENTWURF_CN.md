## 正文

**开场（指第 10 页）**
我负责数据采集，和 Jonas 一起。我们的任务是给 KI 准备它要分析的数据。因为我们没有真实企业的数据，所以做的是模拟数据，但结构和真实的 ERP 导出一样，以后可以直接换成真实数据。

**左边：数据从哪来**
左边是一家虚构纸箱厂的 ERP 数据块：公司画像、变体和物料清单、销量和成本、客户和竞品。产品的尺寸和规格参考了公开的纸箱目录，每条都写明来源。销量、利润这些业务数字是虚构的，并且标记为 SYNTHETIC。

**中间：怎么处理**
中间是流程，全部用 Python 脚本自动完成。先在一个地方定义好所有字段，从这里自动生成 JSON Schema 和一个 Excel 模板。数据填进 Excel 以后，脚本检查数据，然后转成 JSON。

我们的测试分三层：第一，检查规则能不能拦住错误数据；第二，Excel 转出来的数据和原始数据是否一致；第三，在浏览器里把文件上传到原型，看结果对不对。现在一共 71 个自动测试，全部通过。

**右边：交付什么**
右边是交付物。最重要的是一份 JSON 格式的产品数据，以及约定它格式的 JSON Schema，这是我们和概念组、实现组之间的数据约定。另外有字段说明和测试用例目录，测试用例目录写明了每个特殊情况下 KI 应该给出什么建议，比如一个只卖给单一大客户的特殊尺寸。

**现状和下一步**
上周我们和团队过了一遍第一版字段，反馈不错。我们定下来：交付格式用 JSON；数据里只放客观的产品信息，比如“必须保留”这种判断以后由用户在界面上选。现在概念组在根据我们的字段整理完整版本，字段定下来以后，我们出 Schema 第一版，再生成完整的数据包。

## 可能被问的问题

| 可能的问题 | 回答要点 |
| --- | --- |
| 为什么用模拟数据，不用真实数据？ | 没有可用的企业数据；结构按真实 ERP 导出设计，以后可以替换。如果 Steffen 能提供匿名数据，我们可以直接接入。 |
| 为什么选纸箱？ | 产品简单，变体主要靠尺寸、瓦楞、印刷区分，容易理解；有公开目录可参考。需要 Steffen 确认这个试点案例。 |
| 数字是怎么定的？ | 尺寸和规格来自公开目录并写明来源；销量、利润、客户数是假设，假设和理由会写进文档。 |
| 怎么保证数据正确？ | 三层自动测试；每次改动后重新跑；数据有错就不输出，并给出检查报告。 |
| 以后怎么接真实 ERP？ | 我们的数据块按 ERP 导出的结构设计，接口怎么接由概念组在概念里说明；数据格式不用变。 |
| 和 Jonas 怎么分工？ | Jonas 负责业务：产品案例、参考数据、假设和合理性；我负责技术：字段、Schema、脚本、检查和交付。 |
| 下一步什么时候完成？ | 字段定下来以后出 Schema 第一版，然后生成数据包，交给实现组联调。 |
